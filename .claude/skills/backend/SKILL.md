# Backend

Eden API is an ASP.NET Core app (`net10`) in `backend/Eden.Api`, backed by PostgreSQL through EF Core. Controllers only handle HTTP. Entities own persistence through `EdenAppContext`.

## Keep this skill current

When the user asks for a change to backend structure, update this file in the same change. Structure means folders, how controllers, models, DTOs, and helpers are split, persistence access, or the test layout.

A new endpoint that follows the rules already written here does not need a skill edit. If the requested change replaces a rule, rewrite that section so it describes the new structure and drop the old one. Keep `.github/copilot-instructions.md` in sync when a rule it also states changes.

## Documentation

When you add or change a complex feature, write or update a markdown note for it in the same change. Complex means a multi-step flow, matching or calculation rules, or other behavior that is hard to see from the code alone. A simple endpoint that only lists or edits one entity does not need its own note.

Feature notes go in `docs/` at the repo root. Link a new note from `README.md`. Update `README.md` when a user-facing area is added or its behavior changes; leave it alone otherwise.

## Running

- Everything: `process-compose up` from the repo root (Postgres + pgAdmin, migrations, API with `dotnet watch`, frontend).
- API only: `cd backend/Eden.Api && dotnet watch` (http://localhost:5190, Swagger at the root).
- Build: `dotnet build Eden.sln` from the repo root.

## Folder map

```
backend/Eden.Api/
  controllers/      # HTTP only
  DTOs/             # request and response types that are not the entity
  data/             # AppDbContext
  helpers/          # EdenAppContext and other pure/static helpers
  models/           # entities and their static persistence methods
  Migrations/       # EF Core; do not edit migrations that already shipped
  Program.cs
```

Namespaces: `Eden.Api.Controllers`, `Eden.Api.Models`, `Eden.Api.DTOs`, `Eden.Api.Data`, `Eden.Api.Helpers`. Use block-scoped `namespace X { }` like the existing files. One public type per file; the file name is the type name. Nullable reference types are on.

## Controllers

A controller is `[ApiController]`, extends `ControllerBase`, sets `[Route("api/<name>")]`, and returns `IActionResult`. It never takes `AppDbContext` and never runs queries.

```csharp
[HttpGet("{id}")]
public async Task<IActionResult> GetById(int id)
{
    var food = await Food.GetFoodByIdAsync(id);
    if (food == null)
    {
        return NotFound();
    }

    return Ok(food);
}
```

- Request validation lives in a private method that returns `IActionResult?` (`null` means valid): `_validateFoodRequest(Food food)`.
- Bind the entity on create. Bind an `Update<Entity>Request` DTO with nullable fields on update, then merge it onto the existing row (`food.Name ?? existingFood.Name`) and validate the merged entity.
- Missing rows return `NotFound`. Create returns `CreatedAtAction(nameof(GetById), ...)`. Delete returns `NoContent`. `InvalidOperationException` from the model (unique-name violation) becomes `Conflict(ex.Message)`.

Existing prefixes: `/api/food`, `/api/load`, `/api/family`, `/api/distribution` (check the controller before adding a new one).

## Models

Entities are active records in `models/`. Properties are the columns. Static methods load and save through `EdenAppContext.Context.WithDbContext(db => ...)`. Do not open a context any other way.

- Primary keys are `int? Id`, generated by the database.
- `CreatedAt` uses `[DatabaseGenerated(DatabaseGeneratedOption.Computed)]` with a DB default of `NOW()`.
- Unique names use `[Index(nameof(Name), IsUnique = true)]`. Catch `DbUpdateException` with Postgres `SqlState == "23505"` and rethrow as `InvalidOperationException` with a readable message.
- Method names follow the existing style: `GetFoodsAsync`, `GetFoodByIdAsync`, `AddFood`, `UpdateFoodAsync` (instance), `DeleteFoodAsync`.
- Add a `DbSet` in `AppDbContext` and configure foreign keys explicitly in `OnModelCreating`. Nullable FKs use `DeleteBehavior.SetNull`.
- Schema changes get a new migration: `cd backend/Eden.Api && dotnet ef migrations add <snake_case_name>` (e.g. `create_<entity>_table`). Do not edit a migration or `AppDbContextModelSnapshot` that is already in the tree.

## DTOs and helpers

Add a DTO in `DTOs/` only when the HTTP type is not the entity: partial updates (`UpdateFoodRequest`), aggregated responses (`DistributionDto`). Use a `record` with nullable properties for update requests.

Put logic that does not need the database in a static helper in `helpers/`. Callers load entities and pass them in.

## Tests

There is no backend test project yet. When you add pure logic (a calculation, matching, a helper) that needs a test, propose adding `backend/Eden.Api.Tests` (xUnit) and ask before creating it.

## Do not

- Inject `AppDbContext` into a controller or query EF from a controller
- Add a repository or service layer beside the entity
- Return an anonymous object when a DTO is the pattern for that response
- Hand-edit `Migrations/` history instead of adding a migration
- Leave a complex feature change undocumented
